# AI2BI 分析规则

> 本文件约束 Agent 的数据分析行为，优先级仅次于安全铁律。

## 一、证据铁律

1. **每个数字必须有来源**：[SQL] / [计算] / [模型推导]
2. **[SQL] 优先**：能用 SQL 算的不要用模型算
3. **[计算] 必须透明**：标注公式和输入值
4. **[模型推导] 必须警告**：标注"无 SQL 依据，需用户确认"
5. **禁止编造**：Evidence Pack 中没有的数据，不得出现在分析结论中

## 二、分析边界

| 分析类型 | 允许 | 证据要求 |
|---------|------|---------|
| 趋势分析 | ✓ | 至少 2 个时间点数据，由 SQL 产出 |
| 结构拆分 | ✓ | 分项值 + 总值，由 SQL 产出 |
| 排名 | ✓ | ORDER BY 结果，由 SQL 产出 |
| 异常检测 | ✓ | 需标注阈值定义和判断依据 |
| 同比/环比 | ✓ | 由 SQL 或后端计算，不由模型算 |
| 归因分析 | 限制 | 需专属归因 Skill，默认禁止因果断言 |
| 预测 | 禁止 | 不做任何数值预测 |

## 三、[SQL] 标签使用

- 直接引用 SQL 查询结果中的数值
- 标注格式：`1,234,567 [SQL]`
- 后端会从查询结果中提取所有数值，作为 sourced_numbers
- 分析 LLM 只能引用 sourced_numbers 中存在的数值

## 四、[计算] 标签使用

- 基于 sourced_numbers 中的值做简单计算（减法、除法、占比）
- 标注格式：`12.3% [计算: 1234/10000]`
- 公式必须透明，输入值必须可追溯到 [SQL]
- 复杂计算（如标准差、回归）应由 SQL 或后端完成

## 五、[模型推导] 标签使用

- 模型基于业务经验做的估算或判断
- 标注格式：`约5000 [模型推导: 无SQL依据，需用户确认]`
- 必须附带警告
- 前端展示时使用橙色警告标记
- 质检时 [模型推导] 数量过多会触发警告

## 六、输出结构

每个分析回答必须包含：
1. **结论**（只含已验证的陈述，每个数字标注来源）
2. **关键发现**（趋势/结构/排名/异常，每条附数据来源）
3. **口径与范围**（指标定义、时间范围、来源表、过滤条件）
4. **证据标注汇总**（N 个 [SQL]，N 个 [计算]，N 个 [模型推导]）

## 七、禁止行为

1. ❌ 编造 Evidence Pack 中不存在的数字
2. ❌ 将 [模型推导] 伪装成 [SQL]
3. ❌ 省略来源标签
4. ❌ 将相关性表述为因果关系
5. ❌ 做任何数值预测
6. ❌ 在数据不足时强行给出结论
