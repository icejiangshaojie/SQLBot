# 权限、证据与治理规则

## 治理目标

AI2BI 的安全和可信不是“模型被提示不要做什么”，而是每一次资产读取、SQL 执行、结果展示、导出、记忆写入和报告访问都可验证、可审计、可撤销。

## 权限模型

权限按以下对象叠加，最终取交集：

```text
用户身份
  ∩ 工作区权限
  ∩ Agent 授权
  ∩ 数据源权限
  ∩ 表权限
  ∩ 字段权限/脱敏策略
  ∩ 行权限
  ∩ 导出权限
```

| 对象 | 需控制的动作 |
| --- | --- |
| 工作区 | 加入、管理、查看资产、使用数据源 |
| Agent | 使用、维护、审核、发布、授权 |
| 数据源 | 连接管理、查询、导出 |
| 表和字段 | 浏览、查询、查看样例、导出、维护语义 |
| 指标和规则 | 查看草稿、编辑、审核、发布、弃用 |
| Evidence 与报告 | 查看、复制 SQL、下载、重跑、删除 |
| Memory | 创建、查看、编辑、删除、提升为团队资产 |

API 不得使用默认 `user_id=1` 或客户端传入用户 ID 作为权限依据。所有资源查询、更新和删除必须从认证上下文取得当前用户与工作区，并验证资源归属或授权。

## SQL 强制执行规则

执行前必须完成：

1. 从当前用户、工作区、Agent 和数据源解析最终策略。
2. 用 AST 解析 SQL，只接受允许方言的只读语句。
3. 校验所有表同时满足数据源白名单和 Agent 表策略。
4. 校验字段访问权限、敏感等级和脱敏表达式。
5. 注入并验证行权限，不能仅要求模型在 SQL 文本中“记得加条件”。
6. 校验必需分区、业务必需过滤、LIMIT、扫描和超时限制。
7. 执行并记录策略决策与实际 SQL。

若执行策略与 Agent/Skill Prompt 发生冲突，以执行策略为准。

## Evidence 规则

Evidence 是结果可信度的一部分，不能只存一段 SQL 或前几行结果。每个 AnalysisTask 至少保存：

- `user_id`、`workspace_id`、`datasource_id`、`chat_id`、`record_id`、`analysis_task_id`。
- 路由结果、Agent/Skill/Metric/Rule/Template 的解析版本。
- AnalysisContract、AnalysisPlan、全部已执行 SQL 与参数摘要。
- 每条查询的结果 schema、行数、数据时间、结果 hash 和受控样本。
- `[SQL]`、`[计算]`、`[模型推导]` 三类事实及其引用关系。
- 完整分析答案、QA 结果、生成模型、Token、延迟、错误和取消原因。

Evidence 的访问权限不高于原始数据权限。用户没有权限访问原表或敏感字段时，不得通过 SQL、样本、导出或数字明细绕过限制。

## QA 分级

| 级别 | 行为 | 示例 |
| --- | --- | --- |
| 提示 `info` | 展示但提示用户 | 非关键可选分析未执行 |
| 警告 `warning` | 可以展示，标记风险 | 数据缺失、结果量偏小、模型推导 |
| 硬拦截 `block` | 不执行或不展示不合格结论 | 表字段越权、必需过滤缺失、无来源经营数字、禁止预测 |

以下默认硬拦截：

- SQL 非只读、表越权、字段越权、行权限无法验证。
- 未满足指标定义的强制过滤或时间口径。
- 回答将无法引用 Evidence 的数字作为数据事实。
- 无专项授权的预测、因果归因或跨域数据合并。
- 数据结果为空却输出具体经营数字。

以下默认警告：

- 有效行数不足以支持趋势或异常判断。
- 结果中关键字段 NULL 比例高。
- 查询使用了弃用资产版本。
- `[模型推导]` 未转化为可验证查询。

## 模型输出限制

1. 只能把 `sql` 与 `backend_calc` 事实表述为已验证事实。
2. `model_inferred` 必须明确标注“无 SQL 依据，需用户确认”。
3. 模型不能把相关性表述为因果关系，除非已发布专项 Rule/Skill 定义因果方法和证据要求。
4. 未启用预测能力的 Agent 不得输出未来数值或趋势预测。
5. 模型不能要求用户绕过权限、手工提供敏感明细或复制未脱敏结果。

## Memory 规则

| 范围 | 内容 | 管理方式 |
| --- | --- | --- |
| 个人 | 展示偏好、已确认别名、常用时间范围 | 用户可查看、编辑、删除、设置到期 |
| 团队 | 经审核的团队约定 | 资产流程维护 |
| 全局 | 术语、统一口径、共用规则 | 只能通过 Domain/Metric/Rule/Skill 发布 |

Memory 不得保存权限、数据源密钥、敏感明细、未审核指标口径或可绕过强制过滤的指令。

## 运行限制

P0 默认限制如下，具体值可按数据源配置收紧：

| 项目 | 默认限制 |
| --- | --- |
| 单任务 SQL 数 | 3 条 |
| 单条结果行数 | 1000 行 |
| Evidence 明细行数 | 100 行，分析 Prompt 再按模板摘要 |
| 总 SQL 执行时间 | 60 秒 |
| LLM 调用 | SQL 生成 1 次、分析解释 1 次，受控重试 |
| 导出 | 按数据源和字段权限单独校验 |
| 并发任务 | 按用户、工作区和数据源限流 |
| 取消 | 用户可取消后续查询和模型调用 |

超出限制时返回明确原因和可选缩小范围，而不是静默截断后继续给出完整性结论。

## 审计与保留

- 资产变更记录创建人、审核人、版本、原因和影响范围。
- 查询与报告记录用户、权限决策、资产版本、执行摘要和 QA。
- 敏感结果样本、导出和模型上下文按企业数据保留策略处理。
- 删除用户 Memory 不应删除已发布资产；删除报告不应破坏必要审计记录，具体保留期限由治理策略定义。
