# 数据资产与上下文规范

## 目标

业务知识必须被维护为可查、可审、可发布的资产，而不是散落在 Prompt、聊天记录、Excel 或个人经验中。运行时只引用已发布的资产版本；一次分析产生的结果则作为运行产物独立保存。

## 统一资产外壳

每种定义资产都应拥有以下公共字段。现有模型可逐步迁移，不要求一次性替换所有表。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `asset_id` | 是 | 内部主键 |
| `asset_key` | 是 | 稳定业务标识，例如 `corp_deposit.balance` |
| `asset_type` | 是 | domain、table、field、metric、rule、template、agent、skill、test 等 |
| `name` | 是 | 面向用户的中文名称 |
| `domain_ref` | 是 | 所属业务域稳定引用 |
| `workspace_id` | 是 | 所属工作区或租户 |
| `owner` / `owner_team` | 是 | 业务与技术责任归属 |
| `status` | 是 | draft、review、published、deprecated、archived |
| `version` | 是 | 发布版本，建议语义化版本 |
| `source_kind` | 是 | file、db、datasource、import、generated |
| `source_uri` | 否 | 源文件、数据源或导入批次地址 |
| `created_by/created_at` | 是 | 创建审计 |
| `updated_by/updated_at` | 是 | 更新审计 |
| `reviewer/reviewed_at` | 发布必填 | 审核信息 |
| `change_reason` | 更新必填 | 变更原因 |

资产状态流转：

```text
draft -> review -> published -> deprecated -> archived
```

发布后的资产不可原地修改；应创建新版本并重新审核。运行中的 AnalysisTask 始终引用已解析版本。

## 资产类型与录入要求

### 业务域 Domain

| 必填 | 可选 |
| --- | --- |
| `code`、中文名称、范围 `in_scope`、非范围 `out_of_scope`、负责人、业务线 | 同义词、相邻域、背景说明、标签、文档链接 |

业务域必须说明边界。例如“对公存款”不应隐含包括零售存款、理财或信用卡余额。

### 数据源 Datasource

数据源是执行层资产，连接信息不应写入 Skill 或 Markdown。

必填信息：数据源标识、方言、工作区、负责人、可用状态、连接治理方式、默认时区、数据新鲜度和访问策略引用。

### 表 Table 与字段 Field

表与字段分为两层：

1. **执行白名单**：实际可查询的 `CoreDatasource/CoreTable/CoreField`，负责连接、checked 状态及行列权限。
2. **语义字典**：业务含义、字段角色、聚合规则、样例值、质量和血缘，用于 Agent 理解和资产浏览。

两层必须通过稳定的 `datasource_id + schema + physical_name + field_name` 映射，不能只依赖表名字符串。

表必填：数据源引用、schema、物理表名、中文说明、层级、更新频率、数据负责人、可用状态。

字段必填：表引用、物理字段名、类型、中文说明、序号、角色（dimension/metric/filter/partition/key）、是否可空、敏感级别、是否允许查询。

字段可选：聚合方式、枚举样例、脱敏规则、数据质量阈值、业务别名和单位。

### 指标 Metric

指标是语义层的核心，正式运行时应收敛到一套指标模型，避免旧 `Ai2biMetric` 与新 `Ai2biMetricDict` 长期双轨。

| 必填字段 | 说明 |
| --- | --- |
| `metric_key`、名称、别名 | 稳定标识与用户可识别名称 |
| `business_definition` | 指标的业务含义 |
| `calculation` | 明确计算公式 |
| `grain` | 统计粒度，例如客户-日、账户-月 |
| `unit` | 金额、笔、户、百分比等 |
| `time_semantics` | 使用何种时间字段、时点或期间逻辑 |
| `source_refs` | 来源表、字段或已发布 SQL 模板 |
| `dimensions` | 允许拆分的维度 |
| `mandatory_filters` | 必须满足的过滤条件 |
| `owner`、版本、状态 | 治理归属 |

可选字段：默认时间范围、币种、相关指标、口径示例、反例、质量预期、展示格式。

### 业务规则 BusinessRule

业务规则不应只写自然语言。每条规则至少包含：规则类型、适用对象、严重度、内容、正例、反例、负责人和有效期。

规则类型可包括：必需过滤、指标口径、数据质量、跨域隔离、异常阈值、输出禁令和权限限制。

### SQL 模板 SqlTemplate

SQL 模板是已验证的可复用查询，不是训练样例的替代品。

必填：名称、业务场景、SQL 方言、参数定义、关联指标、关联表字段、必需过滤、数据源、负责人、版本和测试状态。

不得在模板中固化用户权限条件；用户的行列权限必须在运行时策略层解析。

### 血缘 Lineage

首期至少维护表级血缘：来源、目标、关系类型、作业或 SQL 片段、来源系统和版本。后续扩展字段级映射、派生公式和任务调度引用。

### Agent

Agent 是业务域的运行时边界。必填内容：

- Agent `code`、名称、业务域引用、负责人、版本和状态。
- `capabilities`：knowledge_qa、data_query、data_analysis。
- `entry_signals`：路由信号及负向信号。
- `skill_refs`、`metric_refs`、`rule_refs`。
- 表策略：专属表、共享表和跨域限制。
- `analysis_templates`：允许的分析模板。
- `qa_config`：警告或硬拦截策略。
- 测试集与发布门槛。

### Skill

Skill 应具备可解析的 Front Matter，而不仅是自由 Markdown。必填信息：

- `skill_id`、名称、版本、层级、所属 Agent/业务域。
- 触发条件与不适用条件。
- 输入契约：所需指标、维度、数据条件。
- 输出契约：允许分析类型、必需口径和输出结构。
- 引用资产：表、字段、指标、规则、SQL 模板。
- 负责人、状态和测试引用。

正文用于保存业务解释、推荐流程、注意事项和示例。

### 测试用例 TestCase

每个待发布 Agent 至少有三类测试：

- 路由测试：问题是否命中预期 Agent/Skill。
- SQL 回归：表、字段、分区、强制过滤和方言是否符合预期。
- Evidence 测试：答案中的数字、公式和口径是否引用正确事实。

## 运行产物规范

以下内容不能当作定义资产保存，也不能反向覆盖资产定义：

- 用户、会话、问题、当前权限和路由决策。
- 已解析的资产版本、SQL、参数、执行时间、结果 schema 和结果 hash。
- EvidencePack、AnalysisFacts、最终答案、QA 结果。
- 模型版本、Token、延迟、错误、取消和审计日志。

运行产物至少应记录：`user_id`、`workspace_id`、`datasource_id`、`analysis_task_id`、`resolved_asset_versions` 和权限决策摘要，以保证隔离和复现。

## 当前模型的演进约束

| 当前情况 | 目标处理方式 |
| --- | --- |
| YAML Agent 与数据库 Agent 双来源 | YAML 作为开发源或导入源，数据库作为已发布运行源，通过显式发布同步和 hash 校验连接 |
| Skill 仅是文件路径和 Markdown | 增加结构化 Front Matter、版本、负责人、状态和引用校验 |
| 旧/新 Metric 双轨 | 确定一套正式 Metric 合同，提供迁移映射和弃用计划 |
| CoreTable/CoreField 与字典分离 | 建立稳定物理对象映射，执行白名单与语义字典各司其职 |
| Evidence 缺少上下文 | 增加用户、工作区、数据源、资产版本、SQL 参数、结果 hash、事实和完整 QA |
| 资产 CRUD 可直接改当前记录 | 引入草稿、审核、发布和版本快照，发布前运行测试 |

## 资产录入顺序

新增业务域时，按以下顺序录入：业务域 -> 数据源与表字段语义 -> 指标 -> 规则 -> SQL 模板 -> Skill -> Agent -> 测试 -> 审核发布。详细操作见 [08-业务知识录入手册](./08-业务知识录入手册.md)。
