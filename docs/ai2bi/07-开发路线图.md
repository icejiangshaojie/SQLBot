# 开发路线图

## 总体原则

先让每一次查询“可授权、可执行、可解释、可复现”，再扩展自动探索和复杂分析。页面数量不作为阶段完成标准；可验证的运行合同、测试和权限闭环才是完成标准。

## Phase 0：聊天内功能闭环

### 目标

在现有聊天链路内打通“取数 → 确定性基础分析 → LLM 解释 → QA → 证据 → 历史恢复”的完整闭环，解决“只取数、不分析”和“有数据却回答没有数据”的核心缺口。

本阶段**不**建设独立任务中心、口径确认、受控多 SQL 编排、服务端取消/重试、资源级授权治理或资产版本发布。既有只读 SQL 校验和表白名单保持不变。

### 后端工作

- 将两个同名 `generate_analysis()` 收敛为 `generate_legacy_chart_analysis()`（兼容手动数据分析入口）与 `generate_evidence_analysis(context)`（统一证据分析入口），修复单独分析路径参数不兼容。
- 新增 `AnalysisContext / AnalysisFact / AnalysisResult` 合同，固定 SQL 结果到分析输出的运行边界。
- 实现纯后端确定性基础分析引擎：直出、汇总、趋势、Top/Bottom N 与占比、双周期对比、受限 IQR 异常；空集、NULL、零分母只输出“数据不足”。
- 重构 QA 为 `passed / warning / blocked`；`blocked` 阻断无来源数字、预测、无支持因果断言，不发送/不保存 LLM 正文，但保留 SQL 与图表。
- 扩展 Evidence：保存 Facts、QA、状态、分析文本、结果 hash、路由与指标上下文；`GET /ai2bi/evidence/{record_id}` 返回扩展详情。
- 清理 `/ai2bi/assets/rules` 的重复 GET 路由。

### 前端工作

- 新增分析运行状态面板与证据链抽屉，展示 SQL、事实、公式、QA 与状态。
- 新增统一 SSE 解码器与 AI2BI 领域类型；修复历史 `ChatRecord` 水合遗漏 `evidence_qa`、`knowledge_answer`。
- 分析/知识回答 Markdown 收敛到净化组件，不扩张直接 `v-html`。

### 测试与验收

- 主查询分析、手动分析、SQL 成功但图表失败仍分析、SQL 失败、空结果、MCP 流式与非流式均有一致状态。
- 固定结果集上汇总、趋势、Top N、零分母、NULL、样本不足计算可复现，不产生伪数字。
- `blocked` QA 下 LLM 正文不通过 SSE 展示、不保存为 `ChatRecord.analysis`，SQL 与图表仍可查看。
- 刷新历史会话后可恢复分析文本、QA 状态和 Evidence 摘要。

## Phase 0.5：权限与治理专项

### 目标

在功能闭环可用后，补齐资源级授权与运行治理，避免扩权。此阶段不新增分析能力，只收敛权限与执行策略。

### 后端工作

- 让 AI2BI API 使用真实认证用户和工作区，移除默认 `user_id=1` 作为业务逻辑输入。
- 为 Agent、Memory、Evidence、资产、测试和 ChatRecord 的读取/修改补充资源归属校验。
- 建立最终 SQL 策略校验入口，合并数据源白名单、Agent 表策略、字段策略、行权限、分区和业务过滤规则。
- 资产版本、发布审批与 YAML/DB 同步；明确“严格按原口径重跑”与“按最新定义重新分析”的区分。

### 前端工作

- 展示当前 Agent、数据源、资产版本与执行轨迹；工作区切换对运行中任务做保护。
- 不新增预测、自由探索或大规模新页面。

### 测试与验收

- 普通用户不能读取或修改其他用户的 Memory、Evidence、Agent 授权或 ChatRecord。
- 越权表、字段、行权限和缺少必需过滤的 SQL 被执行前阻断。
- 已发布资产被弃用后，历史任务仍显示原版本，新任务默认不用弃用资产。

## Phase 1：分析任务与多查询分析

### 目标

Phase 0 已完成单结果集的确定性基础分析与 Evidence 抽屉。Phase 1 将单次查询升级为可持久化的分析任务，并支持有限补充查询（如跨周期同比、缺周期补数）。

### 后端工作

- 新增或明确 `AnalysisTask`、`AnalysisPlan` 的领域模型与迁移（`AnalysisFact` 已在 Phase 0 落地）。
- 将 EvidencePack 输入扩展为多查询结果；支持为缺周期比较（如同比）规划有限补充查询。
- 分析 LLM 输入改为 Contract + EvidencePack + AnalysisFacts；来源标签与公式引用已具备。
- 支持任务创建、列表、详情、重跑与取消（服务端持久化）。

### 前端工作

- 新增分析任务列表与详情路由；支持同一 AnalysisTask 的多查询结果分组展示。
- 展示哪些分析已执行、哪些因数据不足或规则限制未执行。

### 测试与验收

- 固定结果集上汇总、趋势、Top N、占比、环比和异常可复现且精度可验证。
- 跨周期补充查询受数量、超时、行数和权限策略限制。
- LLM 回答中的所有经营数字均可回溯至 SQL 或 backend_calc Fact。

## Phase 2：口径澄清与受控多查询

### 目标

将复杂问题变成用户可确认的分析契约与有限分析计划。

### 后端工作

- 实现 Contract 抽取、歧义检测、候选口径和确认状态。
- 实现 AnalysisPlan 生成与校验，默认最多三条 SQL。
- 支持可选查询失败降级、用户取消、补充查询和计划审计。
- 让后续追问稳定引用上一任务的 Contract、Evidence 和 Facts。

### 前端工作

- 新增口径确认卡、分析模式切换、计划进度和取消操作。
- 结果中展示哪些分析已执行、哪些因数据不足或规则限制未执行。
- 明确区分“重新按原口径运行”和“修改后新建分析”。

### 测试与验收

- 模糊指标、缺失年份、缺失比较基准和跨域问题必须进入澄清或阻断，而不是静默执行。
- 多查询总数、超时、行数、取消和重试均受策略限制。
- 追问不会丢失已确认口径，也不会自动沿用不适用的旧条件。

## Phase 3：资产发布与协作治理

### 目标

让其他同事可以安全、可测试地新增业务域、指标、规则、Skill 和 Agent。

### 后端工作

- 统一 Domain、Metric、Table/Field、Agent、Skill 的稳定引用和版本模型。
- 建立 YAML/文件资产到数据库发布资产的同步、hash 校验和版本快照。
- 完善审核、授权、撤销、弃用、影响分析和资产依赖关系。
- 落实路由、SQL、Evidence 三类回归测试和发布门禁。

### 前端工作

- 完善资产状态、版本比较、审核、依赖图、测试结果和发布影响提示。
- Skill 开发页支持 Front Matter 校验、资产引用选择、指定 Skill 测试和生产路由测试。
- 数据源、Agent、Skill 上下文不再硬编码。

### 测试与验收

- 未通过测试或审核的 Agent/Skill/Metric 不能发布。
- 已发布资产被弃用后，历史任务仍能显示原版本，但新任务默认不用弃用资产。
- 新业务域可按照录入手册完成完整入库、测试和发布，无需改动聊天主流程。

## Phase 4：受控探索与专项能力

### 目标

在治理底座完成后，提供有限的多角度探索和专项分析能力。

### 可选范围

- 受控探索：多维拆分、候选问题、自动图表建议。
- 专项归因：仅对有方法论、规则、数据集和验证标准的领域开放。
- 预测：独立模型、训练数据版本、回测、审批、监控和免责声明齐备后再评估。

### 上线门槛

任何专项能力都必须具备：独立 Agent/Skill、明确输入输出、权限、Evidence 规则、QA、测试集、负责人和回滚策略。

## 实施顺序与依赖

```text
Phase 0 聊天内功能闭环（分析引擎、Evidence、QA、前端展示）
  -> Phase 0.5 权限与治理专项（资源授权、SQL 策略、资产版本）
  -> Phase 1 AnalysisTask / AnalysisPlan / 补充查询
  -> Phase 2 Contract 与多查询计划
  -> Phase 3 资产版本、发布和协作
  -> Phase 4 受控探索与专项能力
```

不得跳过 Phase 0 直接上线探索、预测或跨域自动分析。否则产品表面能力会扩大，但数据权限和结论可信度无法保证。
